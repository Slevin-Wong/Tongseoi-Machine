# 🍬 Tongseoi Machine

### Sugar Water Machine · 糖水机

> **Simmer sweet soup.**
>
> 把一句模糊的灵感，熬成一锅可以直接喂给 AI 图像模型的视觉提示词。

Tongseoi Machine（糖水机）是一套面向 **AI Image Generation** 的创意与 Prompt Engineering Skill。

它不是简单的「帮你写 prompt」。

它试图解决的是更麻烦的那部分：

**当你只有一个想法时，怎么把它变成一组真正有差异的视觉方案；当你已经选中一个方案时，怎么把抽象的“氛围、动作、角度、空间关系”翻译成图像模型真正看得懂的视觉证据。**

它将整个过程拆成两个严格独立的阶段：

```text
                 你的灵感
                    │
                    ▼
        ┌─────────────────────┐
        │  Stage 1 · 创意菜单  │
        │                     │
        │  一次生成 25 个方案   │
        │  结构化、可比较、可挑选 │
        └──────────┬──────────┘
                   │
             选择你喜欢的编号
                   │
                   ▼
        ┌─────────────────────┐
        │  Stage 2 · 完整配方  │
        │                     │
        │  把概念扩写成视觉脚本 │
        │  镜头 + 人物 + 环境   │
        │  光线 + 动作 + 细节   │
        └──────────┬──────────┘
                   │
                   ▼
            Image Generation
```

核心思想只有一句话：

> **不要告诉模型“你想要什么关系”，要告诉它“镜头里具体能看到什么”。**

---

## ✨ 它到底解决什么问题？

很多 AI 图片 Prompt 看起来信息量巨大，实际生成出来却经常是：

* 人物有了，但动作不对
* “背对镜头”写了，脸却莫名其妙出现
* 说了“俯拍”，画面却还是平视
* 说了“前景、中景、背景”，结果前景巨大植物直接把人挡住
* 写了招牌文字，模型却把文字变成乱码
* 场景写得很漂亮，但看起来像没人生活过的摄影棚
* 服装、环境、人物各自漂亮，却互相没有关系
* 想表达身体线条，最后变成简单粗暴的露肤
* prompt 越写越长，画面反而越失控

Tongseoi Machine 针对的，正是这些**“文字写对了，但视觉没有按照文字发生”**的问题。

它通过 Visual Compensation Protocol，把抽象摄影语言转换成图像中的可见证据；同时用 Scene Vitality、World Anchors、Text Rendering、Three-Layer / Weak Foreground 等协议控制空间、环境和构图。

# 🧪 两阶段工作流

## Stage 1 — Creative Menu

先别急着写长 Prompt。

糖水机会先给你一张「创意菜单」。

每个创意都会覆盖 7 个维度：

| 维度      | 解决的问题           |
| ------- | --------------- |
| 🎨 美学路径 | 这张图到底走什么视觉方向    |
| 👤 角色细节 | 发型、妆容、人物气质      |
| 👗 服装造型 | 穿什么，以及为什么适合这个场景 |
| 🌆 环境设定 | 人在哪里，空间是什么样     |
| 📷 摄影   | 景别、构图、光线        |
| 🎬 动作叙事 | 人正在做什么          |
| 🧩 特殊元素 | 道具、互动、偶然事件等     |

默认：

**25 个概念 / 批。**

如果你要 100 个、200 个甚至更多，系统会自动拆批，并保持连续编号。

例如：

```text
你：
给我 100 个“雨夜城市少女”的创意

糖水机：
[01] ...
[02] ...
...
[25] ...

已完成 25/100
输入「继续」获取下一批
```

这样做的目的不是故意折磨上下文。

而是避免一个非常常见的问题：

> **创意列表越长，后半段越像前半段的同卵双胞胎。**

```text
+ 高密度中文视觉描述
```

**20 条完整 Prompt。**

每条约 500 字中文正文，并围绕：

```text
镜头
 ↓
人物
 ↓
服装
 ↓
环境
 ↓
光线
 ↓
动作
 ↓
```

**先让镜头发生，再让细节进入镜头。**

# 🧠 最核心的东西：Visual Compensation

这是整个 Skill 最值得拿出来讲的部分。

很多 Prompt 的问题不是「信息少」。

而是信息停留在**抽象层**。

比如：

```text
❌ 背对镜头
```

模型并不知道怎样才算真正的「背对镜头」。

糖水机会进一步把它翻译成：

```text
✓ 肩胛骨轮廓
✓ 后颈与发丝关系
✓ 衣服背面的结构
✓ 人物视线方向
✓ 镜头能看到的后侧物件
```

再比如：

```text
❌ 俯拍一个女孩
```

不会只停留在“overhead shot”。

而是思考：

**如果摄像机真的在上面，这个镜头里到底应该出现什么？**

于是画面可能自然出现：

* 发顶
* 肩膀形成的轮廓
* 地面的几何纹理
* 桌面上的物件
* 鞋尖的位置
* 周围空间的压缩关系

这就是糖水机所谓的：

> **Describe what you can see, not the relationship you want.**

原 Skill 将这种视觉补偿归纳为 7 类常见失败模式：方向、角度、距离、尺度、运动、光线方向、景深，并分别设计了对应的修复方式。

# 🎬 四套环境与构图协议

糖水机并不满足于「人物漂亮」。

它还要求：

**这个世界得像真的存在。**

## 01 · Scene Vitality

一个场景不是背景图。

它应该像一个**正在被使用的空间**。

所以除了：

```text
房间
桌子
窗户
墙
```

还会寻找：

```text
被移动过的椅子
用过的杯子
散落的纸张
磨损痕迹
水汽
灰尘
植物生长
光线变化
```

让环境产生“有人在这里生活 / 工作 / 活动过”的证据。

---

## 02 · World Anchor System

不要用 50 个随机物件把画面塞满。

而是：

```text
少量强锚点
      +
大量弱锚点
      ↓
建立世界运行秩序
```

比如一个厨房真正有说服力的地方，不是“厨房元素很多”。

而是：

**砧板、调味瓶、冰箱磁贴、擦手巾、使用痕迹**共同告诉你：

> 这里真的有人每天做饭。

---

## 03 · Text Rendering System

AI 图片里的文字一直是经典灾区。

糖水机因此把文字视为一个**真实世界中的排版对象**，而不是随便塞几个英文单词。

文字必须有：

```text
真实载体
+
真实位置
+
合理字号
+
真实语言环境
+
明确的 Typography Block
```

例如：

```text
店铺招牌
公交站牌
门牌
菜单
报纸
包装
广告牌
```

而不是：

```text
“请在背景加入 COOL CITY 字样”
```

---

## 04 · Three-Layer / Weak Foreground

经典三层：

```text
Foreground
    ↓
Midground
    ↓
Background
```

但这里有一个很重要的限制：

> **前景是气氛，不是主角。**

所以前景可以负责：

* 虚化
* 遮挡边缘
* 光斑
* 水汽
* 花瓣
* 玻璃反射
* 空间纵深

但不能突然：

```text
一片巨大的叶子：
████████████████
```

把主角脸挡没。

---

# 👗 Body-Line Story

糖水机还有一条很有意思的规则：

> **一张图只讲一个身体线条故事。**

四选一：

```text
肩颈 / 锁骨
腰部曲线
腿部比例
背部轮廓
```

然后通过：

```text
服装剪裁
材质
褶皱
轮廓
姿态
光线
```

去表达。

而不是简单地：

> 剪掉更多布料。

换句话说：

**让服装设计承担视觉叙事，而不是让露肤承担视觉叙事。**

这也是 Skill 对人物、服装和构图之间关系的一种强约束。

# ⚙️ 5 个 VIBE Engines

糖水机内部还有一套创意驱动系统。

| Engine                      | 负责什么          |
| --------------------------- | ------------- |
| **A · Feminine Charm**      | 人物气质、形象、美学基础  |
| **B · Visual Spectacle**    | 光影、材质、瞬间、视觉奇观 |
| **C · Conceptual Core**     | 概念、哲思、视觉隐喻    |
| **D · Domestic Narrative**  | 日常生活、真实感、生活叙事 |
| **E · Constructed Fantasy** | 可解释的幻想、宏大视觉场面 |

其中：

**Engine A 是基础层。**

然后从 B / C / D / E 中选择其他驱动进行组合。

这意味着糖水机并不是简单地：

```text
随机：
美女 + 衣服 + 场景 + 灯光
```

而是在尝试回答：

> **“这张图为什么会长成这样？”**

原 Skill 将这一结构定义为整个创意框架的决策中心。

# 🛡️ 四级 Prohibition System

为了让输出既稳定又可控，糖水机内部还有四级规则：

| 等级            | 含义          | 是否可豁免   |
| ------------- | ----------- | ------- |
| 🔵 Tier Zero  | 范围 / 负向价值守卫 | ❌       |

其中：

# 🎯 为什么不直接“一句话 Prompt”？

因为：

**一条 Prompt ≠ 一个创意系统。**

当你只写：

```text
beautiful girl, rainy city, cinematic lighting
```

你实际上只告诉模型：

> 我要一个“看起来像这样”的东西。

但你没有告诉它：

* 为什么她在这里？
* 她正在干什么？
* 摄像机在哪里？
* 什么东西离镜头最近？
* 什么东西应该清晰？
* 什么东西应该虚化？
* 光从哪里来？
* 雨水落在哪里？
* 环境为什么像真的？
* 哪个视觉元素应该成为注意力中心？

糖水机的目标，就是把这些问题变成**可执行的视觉信息**。

# 🔥 设计哲学

糖水机有几条很简单、但非常硬的原则。

### 1. 菜单和配方不能混

**Stage 1 是菜单。**

**Stage 2 是配方。**

不要在用户还没选菜的时候，把厨房整个炸给他看。

### 2. 字数就是注意力

Prompt 中写得越多，模型越容易把注意力分配给它。

所以：

> **把字写在哪里，本身就是构图。**

### 3. 抽象关系必须变成视觉证据

不要只写：

```text
背对镜头
```

要写：

```text
镜头看到什么
```

### 4. 空间不能是空的

一个世界应该有自己的运行痕迹。

### 5. 前景是气氛，不是主角

不要让前景抢戏。

### 6. 一张图只讲一个身体线条故事

不要试图同时强调：

```text
肩颈
+
腰
+
腿
+
背
```

选择一个。

### 7. 视觉反差要有理由

漂亮不是把两个漂亮东西放一起。

真正有趣的是：

```text
A 的视觉语言
        ×
B 的叙事环境
```

形成意料之外、但看起来又合理的关系。

# 🧰 Debugging：图片“不对”时怎么办？

如果生成结果失败，不要第一反应是：

> “Prompt 再写长一点。”

先判断是哪一种失败。

| 你看到的问题    | 优先检查            |
| --------- | --------------- |
| 人物朝向错     | Orientation     |
| 俯拍不像俯拍    | Angle           |
| 人物太远 / 太近 | Distance        |
| 物体比例错     | Scale           |
| 动作不像在动    | Motion          |
| 光从错误方向来   | Light Direction |
| 背景不该糊却糊了  | Depth of Field  |
| 前景挡住人物    | Weak Foreground |
| 环境像摄影棚    | Scene Vitality  |
| 场景没有生活感   | World Anchors   |
| 招牌文字乱码    | Text Rendering  |
| 身体线条表达混乱  | Body-Line Story |

糖水机把这些视觉失败进一步整理成了对应的修复协议，而不是单纯靠“多加几个关键词”。

# 🍬 Philosophy

为什么叫 **Tongseoi Machine / 糖水机**？

因为它不是：

> “Prompt Generator”

这种冷冰冰的工具名字。

糖水机想表达的是一种创作方法：

**表面简单。**

**入口自然。**

**中间有层次。**

**最后留一点意外。**

像一碗看起来很普通的糖水。

第一口：

> 嗯，甜。

第二口：

> 等等，好像还有东西。

第三口：

> ……这玩意儿怎么还挺上头。

所以它追求的不是：

```text
越复杂越好
```

而是：

```text
Ordinary surface
        +
Unexpected structure
        +
Concrete visual evidence
        =
Interesting image
```

# ⭐ The Golden Rules

如果你懒得读完整个 Skill，记住这 13 条：

1. **Stage 1 = 菜单，Stage 2 = 配方。**
2. **描述你能看到的东西，而不是你想要的关系。**
3. **字数就是注意力。**
4. **🔵 是范围守卫，🔴 是红线，🟡 是弹性，🟢 是优化。**
5. **人物基础始终存在，再组合其他创意驱动。**
6. **画面要建立前景、中景、背景。**
7. **空间不能是空壳，要有世界运行的痕迹。**
8. **背对镜头，就真的要让画面“看起来是背面”。**
9. **孤立的配饰没有意义，要描述它如何连接到人物或环境。**
10. **大面积无信息的布料是视觉浪费。**
11. **前景负责气氛，不负责抢主角。**
12. **一张图只讲一个身体线条故事。**
13. **不要靠制造露肤来表达身体线条，用服装设计表达。**

这些规则来自 Skill 的最终 Master Quick Reference。

```bash
pip install
```
