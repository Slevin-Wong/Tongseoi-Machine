# 🍬 Tongseoi Machine

### Sugar Water Machine · 糖水机

> 你写了三百个字。
> 出来的人还是站在那儿，看着他不知道在看什么。

---

## 😤 先说一件所有人都经历过的尴尬

你写下：

```text
少女站在暴雨中，情绪强烈，电影感，逆光，氛围感拉满
```

出图了。

天是晴的。头发是干的。光从正面来。她看起来像在便利店门口等朋友。

你以为是词不够多，于是加到了三百字、五百字。下次还是这样，只是这次连构图都糊了。

**问题从来不在词的数量。**

---

## 🔍 真正的问题：你写的是评价，模型要的是证据

上面那句话，每一个词都是**你对画面的评价**。

- 「情绪强烈」——评价。什么样的表情算强烈？
- 「电影感」——评价。哪一盏灯、从哪个角度、打在哪块材质上？
- 「氛围感拉满」——评价。谁在拉？拉向哪？

图像模型没有「情绪强烈」这个概念。它只有具体像素。**你给它的每一个评价词，它都会翻译成一次随机猜测。**

而糖水机只做一件事：

> **把「评价」翻译成「从这个机位、这个光线下，镜头里真正出现的东西」。**

举个具体的。

```text
❌ 背对镜头
```

模型不知道怎样才算真正的「背对镜头」，于是它给你一个转过身、回头冲你笑的女孩。

糖水机要求你写的是：

```text
✓ 肩胛骨在薄纱下顶起两道浅棱
✓ 后颈有一小截碎发被汗黏住
✓ 衣料背面那道褶，从肩线斜着落到腰侧
✓ 她的视线落在画面左外，肩膀没有跟着头转
```

这五句里没有一句是评价。

**这就是它和「帮你写 prompt 的工具」的根本区别：它不给你词库，它给你一套判据，让你自己发现哪里写错了。**

---

## 📐 它凭什么敢当判据？

因为所有阈值都是**量出来的**，不是想出来的。

基准是一份 294 条的参考语料。每一条规则背后的数字，都是在那 294 条里数出来的：

| 这件事 | 实测 | 所以规则是 |
|---|---|---|
| 98% | 景别被明确写出 | 不写景别 = 不合格 |
| 91% | 三层词同现 | 三层空间必须有 |
| 只有 6% | 用「前景是…中景是…后景是」三段式 | 禁止三段式（用了反而像机器） |
| 90% | 描述景深与虚化行为 | 必须写焦外 |
| 66% | 描述赤脚或鞋子 | 这项最容易漏，重点盯 |

> 注意第三行。**大部分人的直觉是「三层就要写三个排比句」，而语料里只有 6% 这么写。** 那 6% 就是「AI 味」的来源。

## ✍️ Stage 2 的五道坎

### 坎一 · 人物必须在前 30 字内出场

语料里，人物的首次提及出现在**第 29 个字**（中位数）。

而新手的典型写法是：

```text
❌ 一张以清晨卧室为舞台的摄影作品，采用中近景构图与略微俯视的机位，光线从左侧窗户……
```

六十个字过去了，读者还不知道画面里有个人。

### 坎二 · 三层空间要有，但三段式要死

见上文。**存在**是强制的，**句式**是被禁的。

正确的写法是让层与层之间**靠距离和遮挡咬合**，而不是并列报菜名：

> 门框切掉画面右下角，虚化的；隔着一整张桌子是她，锐利；走廊尽头只剩一片被窗光洗白的空气。

### 坎三 · 前景是气氛，不是主角

新手最爱犯的错：为了「有层次」，在前景放一片巨大的叶子或一盏巨大的灯，把脸挡没了。

> **前景只负责虚化、遮挡边缘、光斑、水汽。它一旦能被叫出名字并占满画面，它就抢戏了。**

### 坎四 · 数字要删，锚点要留

```text
❌ 距地面约一米一的平视机位、俯角约十五度、主辅光比约二比一
✓ 与坐姿视线齐平、略高于人物视线的微俯视、主光明显压过补光
```

**但器材参数一个都不许动。** `85mm f/1.6 1/320秒 ISO 200 5200K` 必须精确——那不是测量，那是规格。

这条规则有一句很残忍的自检：**你会对着一米一较真，说明你在猜；你会说「和她视线齐平」，说明你看过。**

### 坎五 · 结尾是器材，不是形容词

不许有 `masterpiece, best quality, 8k, 超高清`。

真实感由**机身 + 镜头 + 焦段 + 一套物理自洽的参数**承担，直接接在正文最后一句，不分行、不打标签：

> ……Canon EOS R5 配 RF 85mm f/1.2L USM，平视机位，f/1.6，1/320秒，ISO 200，白平衡 5200K，评价测光，眼部识别 AF，曝光补偿 -0.3EV，黑柔 1/8 滤镜，手持。

## 🌪️ 最常见的一种失败：你的天气被偷偷改没了

你给的原稿是「暴雨中拉小提琴」。

很多 AI 会在「安全舒适」的名义下，悄悄改成这样：

```text
❌ 雨后的海边，空气湿润，她安静地演奏
```

**看起来更安全，更好看，更像一张能发朋友圈的图。但它已经不是你给的那个作品了。**

糖水机明令禁止这种偷改，并给出判据：

> **这个天气是在「压迫」人物，还是在「伤害」人物？**
> **前者保留，后者规避。**

| ✅ 保留 | ❌ 规避 |
|---|---|
| 暴雨、巨浪、强风、雷电、浓雾、风雪、湍急水流 | 受灾、伤亡、损毁、灾后废墟、洪水泛滥 |
| 暴雨中的演奏、风中翻飞的长发、逆光轮廓 | 人物受伤、失控、遭遇灾难 |
| 人与自然的**力量对比** | 人被打倒、被吞没、求救 |

而且——**自然现象 ≠ 人为灾难**：

```text
暴雨  ≠ 洪水       巨浪 ≠ 海啸
强风  ≠ 台风灾害    闪电 ≠ 雷击事故
```

**降级黑名单**（出现即判不合格）：

```text
暴雨 → 雨后 / 零星小雨        巨浪 → 平静海面
强风 → 微风 / 无风             逆光 → 均匀柔光
剧烈动态 → 静静站立            有冲突 → 温馨治愈
```

## 🧥 它甚至管到了你的衣柜和姿势

这是很多人第一次用会愣住的部分：**它不只管句子，还管结构。**

### 一件穿搭只有五个槽

| 槽位 | 填充率 |
|---|---|
| 1️⃣ 主体（上衣+下装，或一件式） | 100% |
| 2️⃣ 覆盖层（外套，**默认敞开**） | 33% |
| 3️⃣ 足 | 89% |
| 4️⃣ 附件 | 77% |
| 5️⃣ 腿袜 | **默认不存在** |

中位数填 4 槽。彩色最多一种。

**腿袜不是「少用」，是「不存在」**——除非你点名。理由很硬：它是唯一一件**不改变任何结构、却能一次抹掉整条腿线**的衣服。

> 🧊 冷了怎么办？顺序是 **换下装 → 换鞋 → 加外套**。前三项都保留腿线，加袜子让腿线归零。

### 一个姿势是六槽，不是标签

支撑面 → 下肢 → 骨盆 → 躯干 → 上肢 → 头，再加三个向量：**重心 / 视线 / 张力**。

> ⚖️ **先定骨盆。** 骨盆跟着腿走，其余一切跟着骨盆走。

内置 **185 套真实穿搭**、**288 个姿势配置**——但它们是**骨架，不是句子**。取一行、填向量、按机位重推。

## 🎨 发色不是选个颜色，是六个问题

| 维度 | 要回答什么 |
|---|---|
| ① 颜色本体 | 底色 / 辅助色 / 点缀色 |
| ② 空间分布 | 十三个区域里，颜色**实际看得见**在哪 |
| ③ 染色技术 | 怎么施加的 |
| ④ 图案结构 | 线条 / 色块 / 色带 / 渐变 |
| ⑤ 对比强度 | 六种机制里靠哪一种 |
| ⑥ 质感光泽 | 表面怎么对光反应 |

写完跑八字段自检：**至少五项，位置与图案必填。**

因为只写颜色不写位置，模型会把颜色均匀铺满整个头——这就是「染了发」和「有一头有性格的头发」的全部区别。

## 🎯 什么时候它最好用

✅ **你卡在「改哪里」**

图不对，但说不清哪儿不对。它有专门的排查表：

| 你看到的 | 去查 |
|---|---|
| 人物朝向错 | Orientation |
| 俯拍不像俯拍 | Angle |
| 前景挡住人物 | Weak Foreground |
| 环境像摄影棚 | Scene Vitality |
| 招牌文字乱码 | Text Rendering |
| 天气比原稿弱了 | 创意保真闸 |

✅ **你要批量产出一批有差异的方案**

25 个创意一次给，7 个维度全透明，挑完再展开。

✅ **你的原稿有强设定，不想被 AI 抹平**

地标、品牌、道具、天气、动作——它默认全部保留。

## 🚫 什么时候你会觉得它很烦

诚实说三种：

❌ **你只想一句话快速出图。** 那你不需要它。它要求你先想清楚机位。

❌ **你讨厌被规则管。** 它有四级禁令、28 条金律、5 道坎。规则密度很高。

❌ **你的创意本身就是「什么样的感觉都行」。** 它是一套判定系统，判定需要靶子。没有靶子，它给你的只是一堆正确的废话。

## 🧠 八条设计判断

1. **菜单和配方不能混。** 没选菜之前别把厨房炸开。
2. **字数就是注意力。** 你把字写在哪，模型就往哪看。
3. **抽象必须变成证据。** 别写「背对镜头」，写镜头看到什么。
4. **空间不能是空的。** 一个世界得有使用痕迹。
5. **前景是气氛，不是主角。**
6. **一张图只讲一个身体线条故事。** 肩颈+腰+腿+背一起上，等于一个都没讲。
7. **天气不是灾难，张力不是危险。**
8. **该长就长，但每句都得看得见。**

## 🍬 为什么叫糖水机

因为好图不是靠堆词堆出来的。

它更像一碗糖水：

**看着平淡。喝下去有东西。最后留一点意外。**

```text
Ordinary surface + Unexpected structure + Concrete evidence = Interesting image
```

## 🤝 提 Issue 前请看一眼

如果你要报「某张图生不出来」，最好的格式是：

```text
原稿：我给的是什么
输出：它给的是什么
差在哪：具体哪里不对（朝向 / 角度 / 景深 / 天气 / 文字…）
```

**每一个新的失败样本，都可能变成下一条判定规则。** 这个项目真正在积累的不是 prompt，而是「什么样的语言能让模型稳定地看到画面」。
