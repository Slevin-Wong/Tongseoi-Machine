# 🍬 Tongseoi Machine

### Sugar Water Machine · 糖水机

**让 AI 生图照着你的描述画出来。**

现在它还带了 **1,407 套真人穿搭**的完整拆解。

---

## 👗 先说这次最大的变化

糖水机一直有一件事做得不够好：**衣柜**。

它知道「上衣 + 下装 + 鞋 + 包」这个骨架，也知道彩色最多一种、外套默认敞开。但当你要一套具体的、真实的、有细节的穿搭时，它给你的东西经常是对的，却不具体——「一件米色针织」和「一件米色细罗纹针织、深 V 交叠领口切到锁骨之间、自布腰带绕两圈在腰侧打结、两条长尾垂过下摆、贴身剪裁、自然腰线收口」之间，差的是二十个字的具体度。

**现在它有了 1,407 套真实穿搭，每套都拆到每一件、每一条构造细节。**

| | |
|---|---|
| 穿搭 | **1,407 套** |
| 单品记录 | **7,447 条** |
| 构造细节 | **28,189 条** |
| 覆盖 | 春 / 夏 / 秋 / 冬 / 派对 / 泳装 / 性感 / 内衣 |
| 词汇 | 96 种品类 · 66 种材质 · 87 种颜色 · 15 种图案 |

## 📦 但 151 万字符，加载得动吗？

**加载得动，因为它默认不加载。**

这是这次更新最重要的设计。参照库是一个独立文件，和 skill 同目录：

```
Tongseoi Machine.md                     ← 规则本体，照常加载
Tongseoi Machine.reference.outfits.md   ← 1,407 套穿搭，按需读取
```

**糖水机默认不读它。** 大多数情况不需要——语法加材质加场景已经够用。为了确认「衬衫 + 裙子 + 靴子」去打开 150 万字，是浪费你画图需要的上下文。

**它什么时候会去读**，只有五种情况：

- 你点名了一件它无法定位的单品（pinafore / cowl-neck）
- 你指定了场合或季节，而它给的衣柜显得泛泛
- 组合反复塌成两个槽位，只有上衣和下装
- 它需要一个没用过的配色或材质配对
- 你直接问「这个配什么」

**而且它不会整本读**：

| 动作 | 成本 |
|---|---|
| 读整个文件 | 1,514,260 字符 |
| 读一个品类（如「泳装」） | 59,882 字符 |
| **读 5 行** | **5,372 字符** |

先选品类，再在品类里搜索你要的槽位，读三到五行就关掉。

**大，不等于重。**

## 🔍 核心没有变：评价 → 证据

```text
❌ 背对镜头
```

模型不知道怎样才算「背对」，于是给你一个转过身、回头冲你笑的女孩。

```text
✓ 肩胛骨在薄纱下顶起两道浅棱
✓ 后颈有一小截碎发被汗黏住
✓ 衣料背面那道褶，从肩线斜着落到腰侧
✓ 她的视线落在画面左外，肩膀没有跟着头转
```

四句话没有一句是评价，但每一句都能被画出来。

**穿搭参照库是同一件事，只是发生在衣柜上。** 「米色针织」是评价，「细罗纹、深 V 交叠领口、自布腰带绕两圈、两条长尾垂过下摆」是证据。

## 👁️ 这次还加了第五个身体区域

主视觉区域从四类扩到五类：

```
肩颈锁骨 · 腰部曲线 · 腿部比例 · 背部轮廓 · 胸部曲线
```

一张图只讲一条线，五选一。多人画面不鼓励选同一个区域。

胸部曲线这一区域有自己的表达规范——décolletage definition / bust silhouette / side bust contour / lower bust contour / bodice shaping，每一种都绑定服装结构和镜头条件，而不是露肤程度。

核心判断：

> **这是时装摄影决定，不是露肤预算。** 哪一种可用，由原始姿态、服装结构和镜头决定——绝不通过改变动作或服装去制造。

## 📐 它的判据从哪来

拿 1,407 套真实穿搭逐条量出来的，不是想出来的：

| 实测 | 所以规则是 |
|---|---|
| 94% 的穿搭组合互不重复 | 没有「精选 50 套」可背，只有 1,407 个具体决定 |
| 92% 的构造细节只出现一次 | 任何压缩都是丢信息，不是去重 |
| 86% 是 4–6 件 | 真实穿搭是完成的，不是凑数的 |
| 彩色最多一种（50% 全中性 / 41% 中性+1） | 一条穿搭只有一个彩色 |

**几乎没有重复，这才是重点。** 能泛化的不是那些行，是分布——规则编码分布，参照库提供证据。

---

## 🛡️ 它不会改弱你的原稿

你给的是「暴雨中拉小提琴」。很多 AI 会在「安全舒适」的名义下改成：

```text
❌ 雨后的海边，空气湿润，她安静地演奏
```

更安全，更好看，**但已经不是你给的那个作品了。**

判断只有一句：

> **这个天气是在「压迫」人物，还是在「伤害」人物？**
> **前者保留，后者规避。**

暴雨、巨浪、强风、雷电、浓雾、风雪都可以留——它们是天气，不是灾难。

## 🚫 这三种情况它帮不上

- **你只想一句话快速出图。** 它要求你先想清楚机位。
- **你偏好极简流程。** 它的规则密度很高，自检很多。
- **你的创意本身就是「什么样都行」。** 它是判定系统，判定需要靶子。
